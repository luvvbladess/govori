# Переводчик — веб-версия

Двусторонний ИИ-переводчик «русский ↔ язык собеседника» с аккаунтами и голосом.
Полный дизайн: `docs/superpowers/specs/2026-07-14-translator-web-design.md`.
Контракт перевода: `translator-mode-web-spec.md`.

## Общие беседы на расстоянии

Создавайте отдельные беседы с названиями через «История» → «Новая общая беседа».
У каждой беседы собственная ссылка, история и участники. В одну беседу могут
подключиться несколько человек. Каждый вводит имя и выбирает свой язык; регистрация
приглашённого не обязательна. Сообщения остальных переводятся на язык участника.

История сохраняет все беседы и позволяет переключаться между ними. Переводы
кэшируются для каждого языка. Новый участник получает прежнюю историю на своём языке.
Ошибка одного перевода не удаляет оригинал и переводы остальных; доступен повтор.

Приглашение, список участников и выход находятся в «Настройках беседы» — кнопка
с тремя точками рядом с настройками интерфейса. Эта панель не занимает место в чате.
После копирования ссылки панель закрывается. Доступ к истории проверяется по членству;
ссылка разрешает подключиться к группе, поэтому делитесь ею с нужными людьми.

Кнопка «Аа» позволяет выбрать размер текста чата: мелкий, обычный, крупный или
очень крупный. Выбор сохраняется в этом браузере. По умолчанию используется 18 px.
Настройка действует на оригиналы и переводы, включая ранее загруженные сообщения.

Беседа обновляется каждые 1,5 секунды. Запись и живой режим используют язык участника.
Старые беседы и сообщения сохраняются при автоматической миграции.

В живом режиме строка «Сейчас говорит: Имя» появляется над чатом, а статус речи — в списке участников
по началу речи, исчезает после паузы или остановки микрофона. При обрыве связи статус
истекает автоматически. Открытый микрофон в тишине не считается речью.

Кнопка «Отменить запись» закрывает микрофон и отбрасывает ещё не отправленную
запись или ожидающие голосовые фразы. Она доступна при запуске микрофона, записи
и обработке. Уже отправленные сообщения живого разговора остаются в истории.

Кнопка «Голос» открывает выбор голоса озвучки. Выбор сохраняется в этом браузере,
действует и на старые карточки; смена голоса останавливает текущую озвучку.
Кэш аудио разделён по голосу и модели.

«Выйти» в настройках беседы прекращает участие: беседа исчезает из вашей истории,
а ваше имя — из списка участников. Общая история остаётся у остальных, включая
сообщения вышедших людей. Вернуться можно по приглашению. Переключение на личный
диалог или другую беседу само по себе не прекращает участие.

## Текущий сервер

Переводчик: **https://lexiqs.space**. Другой сайт на IP сервера обслуживается
отдельным правилом nginx; домен переводчика на него не направляется.

Приложение: `/opt/lexiqs/app`, сервис: `lexiqs.service`, внутренний порт: 3011.
Изолированный Node.js 22: `/opt/lexiqs/runtime`. Сервис запускается от отдельного
пользователя `lexiqs`, автоматически перезапускается и стартует после перезагрузки.
Локальная база аккаунтов и личных диалогов перенесена через SQLite backup.
Сессии старого сервера недоступны — пользователям потребуется войти снова.

HTTPS: `/etc/letsencrypt-lexiqs`, обновление сертификата — таймер
`lexiqs-certificate.timer`; nginx: `/etc/nginx/sites-available/lexiqs`.
Сертификаты и Node других сайтов не изменяются.

Повторный деплой: `python ops/deploy.py` (нужен локальный `paramiko`).
Скрипт читает SSH-реквизиты из игнорируемого Git файла `serv.txt`, переносит
исходники, сохраняет серверные `.env` и `data`, устанавливает зависимости и
перезапускает сервис. Перед следующими обновлениями делайте резервную копию
серверной директории `data` средствами SQLite backup.
Логи: `journalctl -u lexiqs -n 100 --no-pager`.

## Запуск локально

1. `npm install`
2. Скопировать `.env.example` в `.env`, заполнить `OPENAI_API_KEY` и `SESSION_SECRET`.
3. `npm start`
4. Открыть `http://localhost:3000`.

Голосовой ввод (`SpeechRecognition`) требует HTTPS или `localhost` — в проде это
даёт Cloudflare, локально `localhost` уже считается secure context.

## Тесты

`npm test` — юнит- и интеграционные тесты (`node:test`), включая все 9 сценариев
из раздела «Обязательные тесты» спеки. Реальный OpenAI API не вызывается —
`openaiClient.callOpenAI` подменяется фейком в тестах.

`node ops/check_shared_ui.cjs` — отдельная локальная браузерная проверка четырёх
участников, трёх языков, статуса речи и выхода из группы. Требуются установленный
Playwright и его Chromium; можно выбрать установленный Chrome через переменную
`PLAYWRIGHT_CHANNEL=chrome`. Провайдер, микрофон и события WebRTC в этой проверке
имитируются; рабочий сервер и его данные не используются.

## Деплой на Ubuntu VPS + Cloudflare

1. Установить Node.js >= 22.12 и build-essential (нужен для сборки `better-sqlite3`/`bcrypt`
   из исходников): `sudo apt install -y build-essential python3`.
2. Склонировать репозиторий на сервер, `npm install --omit=dev`, заполнить `.env`
   (реальный `SESSION_SECRET`, `OPENAI_API_KEY`).
3. Запустить процесс постоянно, например через systemd или pm2 (`pm2 start server.js --name translator`).
   Установить `NODE_ENV=production` (в `.env` или окружении сервиса) — иначе Express
   может включать stack trace в ответ об ошибке.
4. В Cloudflare: A-запись на IP сервера, SSL/TLS режим Full (или Full strict, если
   на origin тоже настроен сертификат) — этого достаточно, чтобы браузер видел
   `https://` и разрешал доступ к микрофону.
5. Бэкапить директорию `data`: базы и постоянные ключи Web Push
   `push-keys.json`. Смена ключей потребует повторного включения уведомлений
   на устройствах.

## Уведомления на телефоне

Колокольчик открывает настройки голоса и уведомлений. Нажать «Включить
уведомления» и разрешить их в браузере. Разрешение запрашивается только после
нажатия. Уведомления приходят о новых сообщениях общих бесед, включая закрытую
вкладку; нажатие открывает соответствующую беседу. Собственные сообщения и
беседы, из которых пользователь вышел, уведомлений не создают. В уведомление
передаются имя автора и название беседы, без текста сообщения.

Нужны HTTPS, браузер с Web Push и разрешённые системные уведомления. На iPhone
и iPad с iOS/iPadOS 16.4+ сначала добавить сайт на экран «Домой», затем открыть
его оттуда и включить уведомления. Основание:
[WebKit: Web Push on iOS and iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

При старте создаются постоянные ключи `data/push-keys.json`; они игнорируются
Git. Для управляемых ключей можно задать обе переменные `VAPID_PUBLIC_KEY` и
`VAPID_PRIVATE_KEY`. `VAPID_SUBJECT` задаёт контакт в формате HTTPS или `mailto:`.
Не переносить приватный ключ в исходники. Service worker не кэширует беседы,
ответы API или аудио.

`node ops/check_push_ui.cjs` проверяет настоящий service worker в Chrome:
включение/отключение, уведомление при закрытой вкладке и переход в беседу.
Внешняя доставка имитируется; реальное получение на телефоне следует проверить
после отдельной разрешённой выкладки.

## Мобильная проверка

`node ops/check_mobile_ui.cjs` проверяет 15 размеров от 280×320 до 1024×768,
включая короткие горизонтальные экраны, три языка интерфейса и обе темы.
Проверяются длинные имена и сообщения, увеличенный шрифт, речь, отмена,
окна настроек, приглашений и регистрации. `QA_BROWSER=webkit` выбирает WebKit;
`QA_MOBILE_QUICK=1` сокращает набор до трёх размеров. Требуется Playwright и
установленный соответствующий браузер. Данные и микрофон имитируются локально.
Такая проверка не заменяет проверку физических устройств, экранной клавиатуры
и системных разрешений.

## Переменные окружения

См. `.env.example`: `PORT`, `SESSION_SECRET`, `OPENAI_API_KEY`, `TRANSLATOR_MODEL`.

Для перевода по умолчанию используется `gpt-6-luna` с `reasoning_effort=none`, для
готовых записей — `gpt-transcribe` с подсказкой языка через `languages[]`.
Явно заданные прежние модели сохраняют совместимые параметры запросов.
Основание: [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)
и [распознавание записей](https://developers.openai.com/api/docs/guides/speech-to-text).

Живой режим сохраняет `REALTIME_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe`:
новый `gpt-live-transcribe` не поддерживает используемый `server_vad` и требует
отдельной адаптации начала/конца речи и фиксации реплик. См.
[Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription).
Озвучка сохраняет `gpt-4o-mini-tts`; доступные голоса перечислены в
[официальном описании](https://developers.openai.com/api/docs/guides/text-to-speech).
