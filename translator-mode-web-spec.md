# Режим «Переводчик» — спецификация для веб-версии

## Задача

Это отдельный двусторонний переводчик для пары «русский ↔ язык собеседника». Пользователь не выбирает направление перед каждой фразой:

- иностранное сообщение переводится на русский и запоминает язык собеседника;
- следующее русское сообщение переводится на сохранённый язык;
- при смене языка собеседника, например с китайского на английский, новая иностранная фраза автоматически заменяет сохранённый язык;
- пользователь может явно задать направление фразой вида «Переведи на китайский: Добрый день».

Цель интерфейса — быстрый обмен короткими текстовыми или голосовыми репликами, а не обычный чат с ИИ.

## Состояние пользователя

Хранить состояние отдельно для каждого пользователя или сессии:

```ts
type TranslatorSession = {
  targetLanguage: string | null // например, «Китайский»
}
```

`targetLanguage` — это язык собеседника, на который переводятся русские сообщения. Значение переживает перезагрузку страницы и новую сессию пользователя.

Не нужно хранить длинную историю сообщений для принятия решения о направлении. Достаточно `targetLanguage` и текущей реплики.

## Пользовательские сценарии

### 1. Первый русский текст

Если `targetLanguage === null`, а пользователь отправил русскую реплику без явного указания языка, не нужно гадать. Покажите подсказку:

> Сначала отправьте фразу собеседника на его языке или явно напишите: «Переведи на китайский: ...».

### 2. Иностранный текст

Вход: `你好，你好吗？`

Результат:

```text
Оригинал (Китайский): «你好，你好吗？»
Перевод (Русский): «Здравствуйте, как вы?»
```

После успешного ответа сохранить `targetLanguage = "Китайский"`.

### 3. Русский текст при известной паре

При `targetLanguage = "Китайский"` вход `Мы посетим фабрику` должен дать:

```text
Оригинал (Русский): «Мы посетим фабрику»
Перевод (Китайский): «我们将参观工厂»
```

### 4. Автоматическая смена языка

При сохранённом китайском языке приходит английская фраза. Сервис переводит её на русский и заменяет `targetLanguage` на `Английский`. Следующая русская реплика переводится уже на английский.

### 5. Явный запрос

Вход: `Переведи на английский: как дела?`

Нужно перевести только фразу «как дела?», вернуть английский результат и сохранить `targetLanguage = "Английский"`.

## Контракт backend API

### Запрос

```http
POST /api/translator/translate
Content-Type: application/json
Authorization: Bearer <session-token>

{
  "text": "Мы посетим фабрику"
}
```

`targetLanguage` сервер получает из сессии, а не доверяет присланному клиентом значению. Если в продукте нужен ручной выбор языка, делать это отдельным защищённым endpoint-ом настройки.

### Успешный ответ

```json
{
  "ok": true,
  "sourceLanguage": "Русский",
  "targetLanguage": "Китайский",
  "original": "Мы посетим фабрику",
  "translation": "我们将参观工厂",
  "voiceText": "我们将参观工厂",
  "session": {
    "targetLanguage": "Китайский"
  }
}
```

`voiceText` равен чистому переводу. Он нужен, если веб-версия добавит TTS, и не должен содержать подписи «Оригинал» и «Перевод».

### Ответ без определённой пары

```json
{
  "ok": false,
  "code": "TARGET_LANGUAGE_REQUIRED",
  "message": "Сначала отправьте фразу собеседника на его языке или укажите язык явно."
}
```

### Ошибка перевода

```json
{
  "ok": false,
  "code": "TRANSLATION_FAILED",
  "message": "Не удалось перевести сообщение. Попробуйте ещё раз."
}
```

Не возвращать пользователю сырой текст ошибки провайдера или ключи API.

## Контракт с моделью

Используется один целевой вызов модели-переводчика. Модель должна вернуть только JSON:

```json
{
  "detected_lang": "Китайский",
  "translation": "Здравствуйте, как вы?",
  "new_target_lang": "Китайский"
}
```

Правила для модели:

1. Явный запрос перевода: перевести только полезную фразу на явно запрошенный язык и вернуть этот язык в `new_target_lang`.
2. Нерусский текст: перевести на русский и вернуть исходный язык в `new_target_lang`.
3. Русский текст при известном языке: перевести на `targetLanguage`; `new_target_lang` равен `null`.
4. Возвращать валидный JSON без Markdown и пояснений.

В текущем боте перевод выполняет отдельная недорогая модель `gpt-5.6-luna`. В веб-проекте модель должна быть настраиваемой через переменную окружения, например `TRANSLATOR_MODEL`.

## Защита от неверного направления

Нельзя без проверки показывать ответ модели под подписью «Перевод (китайский)». Модель иногда может повторить русский оригинал вместо китайского текста.

Для известных направлений проверять алфавит результата:

| Целевой язык | Минимальная проверка |
| --- | --- |
| Китайский | Есть CJK-символы; нет кириллицы |
| Русский | Есть кириллица |
| Английский | Есть латиница; нет кириллицы |
| Другой нерусский | Не принимать текст с кириллицей как успешный перевод русского источника |

Если русский источник вернулся русским текстом вместо нерусского перевода:

1. Повторить запрос один раз с жёсткой инструкцией: «верни перевод строго на целевом языке, не копируй русский исходник».
2. Проверить повторный результат тем же правилом.
3. Если он снова некорректен, вернуть `TRANSLATION_FAILED`, не показывать ложный перевод и не запускать TTS.

При определении русского источника использовать и метку модели, и преобладающий алфавит входа. Это важно для смешанного текста:

- `请联系Яндекс` — китайский источник с русским брендом, переводится на русский;
- `Переведи «你好» на китайский` — русский запрос с китайской цитатой, переводится на китайский.

## Обработка ответа модели

Ответ может прийти в блоке ` ```json ` и с LF или CRLF-переносами строк. Парсер должен:

1. Обрезать пробелы.
2. Убрать внешние Markdown-ограждения кода независимо от регистра `json` и типа переноса строки.
3. Распарсить JSON.
4. Проверить обязательные поля и непустой `translation`, если перевод должен быть выполнен.

При ошибке парсинга не пытаться отдать пользователю сырой ответ модели.

## Интерфейс веб-страницы

Минимальный экран:

- индикатор пары: `Русский ↔ Китайский` или `Язык собеседника не задан`;
- лента из карточек «Оригинал» и «Перевод»;
- поле ввода и кнопка отправки;
- кнопка микрофона, если добавляется распознавание речи;
- кнопка «Сменить язык» с явным выбором языка;
- кнопка воспроизведения у `voiceText`, если добавляется TTS.

Показывайте язык результата рядом с переводом. Не скрывайте оригинал: это позволяет пользователю быстро заметить неверное распознавание речи или направления.

## Рекомендации по реализации

- Не хранить API-ключи в клиентском коде. Вызов модели выполняется только на сервере.
- Проверять длину текста, например ограничить одну реплику 4 000–8 000 символами.
- Добавить rate limit на endpoint перевода по user ID и IP.
- Отдельно логировать техническую причину неудачи без текста пользователя и без секретов.
- Сохранять только необходимые данные сессии. Историю переводов делать отдельной opt-in функцией.
- Для голосового ввода: сначала STT, затем ровно тот же текстовый endpoint перевода. Для озвучки использовать `voiceText`.

## Обязательные тесты

1. Первый русский текст без пары возвращает `TARGET_LANGUAGE_REQUIRED`.
2. Китайский текст переводится на русский и сохраняет китайский как целевой язык.
3. После этого русский текст переводится на китайский.
4. Английская фраза переключает пару с китайского на английский.
5. Явная команда переключает язык.
6. JSON в кодовом блоке с CRLF корректно разбирается.
7. Русский текст, ошибочно возвращённый как китайский перевод, приводит к одному retry.
8. Повторный неверный ответ приводит к `TRANSLATION_FAILED`, а не к ложному переводу.
9. Китайская фраза с русским именем и русский запрос с китайской цитатой сохраняют правильное направление.
